# BDL 界面设计规范

本规范用于桌面与 Android 界面的重设计、组件调整和人工视觉检查。目标是紧凑、清楚、轻巧的下载工具：操作直接，内容优先，使用 B 站粉表达品牌。

用户已审核第二轮全页面图稿并授权实施。当前覆盖解析、下载设置弹窗、内容库、收藏夹详情、传输、五类设置、关于及 Android 我的页面。布局以这组图稿为依据，具体逻辑尺寸通过真实组件运行画面校准；不从生成图像或 B 站截图的物理像素反推 dp。

实现使用 Nuxt UI 的按钮、输入、选择器、复选框、开关、进度条、Tabs、菜单和 Modal，以及现有业务封装。页面排版仍由业务组件负责。桌面与手机的实际运行截图已人工检查；这份证据来自模拟原生 API 的真实前端组件，Android 真机字体、触控和原生系统页面仍需设备验收。

## 1. 尺度与层级

- 默认界面不采用展示型大标题、大头像、粗字和高按钮。重要性优先由位置、字重、对比和分组体现。
- 桌面与手机采用接近的字号体系，手机主要增加触控空间，不整体放大文字和图标；平板增加列数和可用区域，不把手机等比放大。
- 紧凑通过减少重复标题、重复配置摘要、多余说明和嵌套卡片实现，不通过把主要信息缩成小字实现。
- 以下尺寸均为默认文字大小、100% 缩放下的逻辑布局目标，非截图物理像素。Web 使用 CSS px 表述，16px 根字号下换算为 rem；Android 设备上的 CSS px 与 dp 映射需实际核对。
- 用户主动放大文字时允许换行、增高和重排。这些默认尺度不是强制最大高度，不用固定高度裁掉文字或操作。

## 2. 字体

产品正文使用现有 Noto Sans SC 字体，品牌沿用现有素材，不引入显示字体。下表为当前默认字级；设备字体设置仍需真机复查，不随页面创造另一套。

| 用途 | 桌面：字号 / 行高 | Android：字号 / 行高 | 字重与使用方式 |
| --- | --- | --- | --- |
| 页面标题 | 18 / 26px | 16 / 24px | 600；页面有清楚上下文时可省略 |
| 弹窗、底部页标题 | 16 / 24px | 16 / 24px | 600；不另加大号宣传标题 |
| 区域标题、表单分组 | 14 / 20px | 14 / 20px | 500–600 |
| 来源标题、账号名称 | 14 / 20px | 14 / 20px | 500–600；长来源名最多两行 |
| 视频、分 P、传输行标题 | 13 / 20px | 13 / 20px | 500；默认一行，按需显示完整内容 |
| 普通说明、表单值 | 13 / 20px | 14 / 20px | 400；不要全页加粗 |
| 按钮、页内标签 | 13 / 20px | 13 / 20px | 500；主要按钮可用 600 |
| 作者、时长、路径摘要、辅助信息 | 12 / 18px | 12 / 18px | 400；不能承载唯一的关键操作 |
| 底部导航标签、非关键紧凑徽标 | 11 / 16px | 11 / 16px | 400–500；仅限短标签 |

默认业务页面不使用 22px 以上标题；手机不使用 18–24px 的列表标题或按钮文字。不能为了填满一行而增大字号，也不能为了塞下内容把正文压到 10–11px。11px 仅用于表中指定的短标签，错误说明、路径选择和操作按钮不使用该档。

速度、时长、大小、百分比使用等宽数字特性，避免更新时跳动；不把整行中文换成等宽字体。正文不增加装饰性字距，不依靠 700–800 字重制造层级。

## 3. 按钮、输入与图标

按钮必须区分可见轮廓、内部图标/文字与完整点击热区；不能只给“一个按钮”指定单一尺寸。以下按用途定义规则，手机端不再统一锁定36px。

| 控件 | 桌面外观 | Android 外观 | 说明 |
| --- | --- | --- | --- |
| 工具栏文字按钮 | 28–32 CSS px仅作紧凑候选 | 依行内文字、留白与B站截图比例校准，暂不定死dp | 调整、更换、筛选等次要操作 |
| 行内胶囊按钮 | 按内容及邻近控件确定 | 参考截图中发布、会员中心等行内胶囊的相对比例 | 不套用底部主操作或图文入口尺寸 |
| 主要下载按钮 | 根据操作区单独确定 | 根据底栏、文字与周边信息单独确定 | 不能由桌面32px或旧Material36px直接推导 |
| 单行输入、选择器 | 跟随同组表单尺度 | 与手机表单行和邻近按钮共同校准 | 不要求所有类型控件高度一致 |
| 独立图标操作 | 分开定义可见图标与外框 | 顶部图标、列表操作和导航图标分别定义 | 图标可见大小不等于按钮完整尺寸 |
| 图标加文字入口 | 用于明确的导航场景 | 参考B站截图的图文分组，整个入口是热区 | 不能把一整个入口当成一个小文字按钮 |
| 复选框 | 可见框与标签行分开 | 可见框与可点击标签/行分开 | 中间态使用横杠，子操作不触发行选择 |

多行输入和增大字号状态按内容调整，不能沿用单行固定高度。主按钮旁的取消、调整、更换等操作保持次要样式。同一操作区通常只有一个实心粉色主按钮；导航、选中行与次要按钮不全部画成实心粉块。

手机下载底栏采用“摘要 + 主要操作”组合，宽度由完整标签、图标、内边距和可用空间决定，不先锁死120–144px。只在单一输入动作或确需独占一行的窄宽度下使用通栏按钮；通栏不意味着更大字体或更高按钮。

## 4. 触控热区与缩放

Android 独立操作以至少 48 × 48dp 的触控热区为目标，可见图标或按钮可以更小。优先用真实按钮的布局空间和内部可见区域分离实现，不用相邻重叠的透明覆盖层；复选框可由对应行的选择标签扩大操作区域。点击子操作时不能同时触发行选择。

桌面密集工具按钮保留至少 24 × 24 CSS px 的点击区域；独立工具按钮通常使用 28–32px 外框。键盘操作始终可见焦点，不能仅靠 hover 暴露唯一操作。聚焦时仅将现有边框变粉，不增加 outline、ring 或外圈光晕；无边框标签可用轻量中性色焦点底。

不要为了修正图稿密度新增全局 `zoom`、`transform: scale()` 或压低根字号的方案。项目现有高密度 Android 宽窗口的 60% 根字号分支需要单独核对字体、弹窗和实际触控面积；不能只依据这张表机械删除，也不能把 CSS 48px 直接当成该分支下的设备 48dp。默认密度与用户文字放大分别验证，不能为了守住紧凑行高抵消用户放大。

触控尺寸依据 [Android 官方无障碍说明](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views#touch-targets)；Web 最小目标及例外见 [WCAG 2.2：目标尺寸](https://www.w3.org/TR/WCAG22/#target-size-minimum)。本规范的默认字号与可见尺寸是 BDL 的设计决定，并非声称平台强制使用这些数值。

## 5. 导航、列表和卡片

| 区域 | 桌面目标 | Android 目标 |
| --- | --- | --- |
| 全局标题栏 | 内容高 42px；品牌字 16px | 内容高 44px；品牌字 16px；另加系统安全区 |
| 侧栏 | 常规宽 150px；导航行高 42px；标签 13px | 平板使用紧凑导航轨，图标 20px，不放大主内容字号 |
| 底部导航 | 不使用 | 内容高 48–52px，图标 20px、标签 11px；另加底部安全区 |
| 来源摘要 | 封面约 96 × 54px；标题 14px | 封面约 72 × 40px；标题 14px；不占据大半首屏 |
| 视频、分 P 行 | 分 P 紧凑行 48px、封面 60 × 36px；普通视频行 72px、封面 64 × 36px | 分 P 行至少48px；有作者信息的普通视频按内容增高；封面 60 × 36px |
| 传输行 | 默认高 56–64px | 默认高64px，封面64×40px；标题/状态两行，进度条贴近底部，不额外预留第三行 |
| 收藏夹入口 | 卡片高约 80–88px；按宽度排一至两列 | 行高约 72px；缩略图约 64 × 40px |
| 我的账号入口 | 使用全局账号控件 | 行高约 64px、头像 32px、名称 14px |
| 我的功能入口 | 不使用单独入口页 | 单行高 48–52px，图标 18–20px、标签 14px |

以上为普通内容的默认范围；双行标题、行内错误或用户放大文字允许增高。不能为了固定行数截掉状态和操作。

标签页使用Nuxt UI UTabs自带的link指示器，由组件计算位置、宽度和切换；不隐藏后另画伪元素或活动边框。横向滚动归外层root，list保留组件库的底边和指示器补偿，避免指示线被裁掉。

列表默认使用细分隔线、对齐和轻量 hover/选中反馈，不给每一行添加明显阴影、粗边框或大圆角。选中状态主要通过复选框表达，密集内容行不整行铺粉色，错误除颜色外还要有文字或图标。

长标题桌面可省略并提供可聚焦的完整信息入口；手机通过详情等触控路径查看完整文本，不能只有鼠标 tooltip。作者、时长、进度不与主标题争用同等字重。封面为辅助识别，课程分 P 共用封面时不能反复放大同一张图。

桌面侧栏保留解析、内容库、传输、设置、关于；Android 保留解析、内容库、传输、我的。账号和主题入口遵循现有平台职责，不因精简而删掉关键入口。不要在全局品牌栏下再堆一个大号 BDL 标题。

## 6. 间距与容器

以 4px 为基础，常用间距为 4、6、8、12、16、20、24px。6px 用于紧凑控件内部，不扩展出任意间距档位。

- 页面内边距：桌面 24px，窄窗口可收紧；手机 12px。
- 内容区块间距：通常 16px；同组表单间距 12px；紧密工具与图标文字间距 6–8px。
- 普通卡片内边距：12px；密集列表行内边距：横向 8–12px、纵向 6–8px。
- 弹窗内边距：桌面 20px、手机 16px；表单标签到控件间距 6px。
- 圆角：输入和按钮 6px，普通容器 8px，弹窗 12px。头像可圆形，不把所有控件做成胶囊。
- 边框通常 1px；阴影只用于需要浮起的菜单、弹窗等，普通列表不逐行悬浮。

不使用大面积无意义留白撑高账号卡、来源摘要或页头。也不为提高密度把所有内容贴在一起；用分组间距区分层级，避免层层套卡片。

手机解析底栏保持紧凑单行：已选数量、当前下载预设 + 调整、下载主按钮；不展示输出格式明细、目录摘要或目录快捷按钮。目录仍在调整弹窗内修改；桌面保留完整摘要。手机媒体列表行左右各留8px，复选框和末尾操作不贴卡片边缘。分页器不绘制外层底色，仅保留可编辑页码输入框。底部导航与系统安全区另算，用户放大文字时允许增高或重排。

## 7. 颜色与主题

品牌参考使用 B 站粉 `#FB7299`，通过现有语义 token 提供各主题的交互色阶；不引入蓝色作为第二主强调色。封面自己的蓝紫等颜色不受此限制。实心主按钮、复选框、焦点和进度使用粉色；结构面使用中性白/灰与炭灰。

粉色底不能自动假定适合白色小字。根据实际色阶选用深色文字，或使用更深的粉色配白字；普通文字的前景与背景对比目标至少为 4.5:1。数值和层级不能仅靠低对比浅灰区分。依据见 [WCAG 2.2：文字对比度](https://www.w3.org/TR/WCAG22/#contrast-minimum)。

深色主题保留页面、区域、卡片、输入和浮层的层级，不用纯黑、大面积粉色或光晕代替层次。成功、警告和失败保留各自语义颜色及文字，不把所有状态都染成粉色。浅深主题沿用同一尺寸和密度。

## 8. 与当前工程的衔接

| 所有权 | 文件入口 | 调整方式 |
| --- | --- | --- |
| 共享颜色、字体、间距与高度 | `apps/desktop/src/shared/styles/tokens.css` | 在现有语义 token 中统一调整，不另起主题系统 |
| Nuxt UI 主题与浮层 | `apps/desktop/src/shared/styles/nuxt-ui.css` | 复用组件库与已有变体，不依赖其未公开 DOM |
| 通用按钮、输入、选择与图标按钮 | `apps/desktop/src/shared/ui/` | 通过 Nuxt UI 组件和公开插槽配置统一尺寸与状态，平台负责额外操作空间 |
| 桌面框架与页面布局 | `apps/desktop/src/desktop/` | 收紧标题栏、侧栏、列表、页头，保留窄窗口行为 |
| Android 框架、密度与安全区 | `apps/desktop/src/mobile/` | 使用现有移动字号/行高 token；同时覆盖 portaled 弹窗和底部页 |

当前共享普通按钮是 13px 文字、34px 最小高；手机已有 13px 列表标题等紧凑 token。这是当前实现事实，不是推荐值的依据。新规范不代表要把现有代码所有值再缩小一轮；先核对属性所有者和实际渲染，再改偏离目标的部分。移除被替代规则，避免追加覆盖、深层选择器和无依据的 `!important`。不为本次重设计新增密度模式、配置开关或旧版兼容分支。

标准交互使用 Nuxt UI 及项目已有封装：输入、多行输入、选择、按钮、复选框、表单错误和弹窗分别由对应组件负责。共享 TextField、Textarea、FormField、命名模板输入和分页跳转已接入 Nuxt UI；原生表单状态样式文件已移除。紧凑字号与外观通过公开的 `size / variant / ui` 配置及现有主题调整，不另写一套原生输入/选择/按钮状态样式。自定义页面构图和媒体列表布局仍由业务组件负责；日期时间类型、命名光标插入和错误描述关联等行为需要验证，不能只替换标签。

## 9. 图稿与实现检查

1. 图稿按本规范收紧字号、头像、封面、控件和留白；保留认可过的页面结构和 B 站粉，不能把旧图的夸张比例当成审批内容。
2. 查看实际运行画面：桌面宽/窄窗口、手机 375px 与常见 390–412px 宽度，以及平板/短横屏；分别查看浅深主题。比较内容的主次、对齐、行距、完整操作和首屏信息量，不把“能显示更多行”当成唯一目标。
3. 同时检查普通/长标题、等待/下载/暂停/失败/完成、加载/空态、设置未保存、下载调整和必要错误。检查按钮焦点、键盘操作、触控目标与相邻操作冲突。
4. 用户文字放大和实际 Android WebView/系统字体设置另行检查，不能通过固定最大行高或反向缩放取消用户设置。Web 文字放大目标见 [WCAG 2.2：文字缩放](https://www.w3.org/TR/WCAG22/#resize-text)。
5. 视觉验收只以亲自查看实际运行截图并人工判断为准，不新增截图比较、DOM/坐标/尺寸合格断言。现有业务 UI 测试和工程检查单独报告；文档写好、图稿完成或构建成功不代表界面已经验收。

项目功能与视觉验证入口见 [开发指南](DEVELOPMENT.md)。

### 下载与命名预设

- 日常操作沿用已记住的预设直接下载；调整弹窗只显示下载预设、输出预览、目录、命名预设、文件名预览和重名策略，不提供调度。
- 设置按“下载与保存、画质与编码、预设管理、应用更新、网络与维护”分组。默认下载/命名与重名策略归入下载与保存；全局质量独立于内容预设；两个预设库集中管理。手机采用“下载保存、画质编码、预设管理、更新、维护”，不以省略号压缩主要分类。
- 预设管理直接显示在设置页，支持分类、搜索、每行设为默认/编辑/复制/删除。管理列表不使用弹窗；只有新增、编辑/复制表单弹出。下载弹窗中保留快捷新增，“管理”关闭弹窗并导航对应列表，保留解析选择。编辑/复制不自动切换当前预设；内置命名只允许设为默认或复制，下载预设至少保留一个。
- 预设库没有草稿时不显示无关的全局保存/恢复默认；其他设置尚未保存时仍保留保存与撤销。编辑器的保存和行内“设为默认”明确执行独立写入，不带入其他设置草稿。
- 清晰度和音质选择器固定“最佳可用”在首位，清晰度的“仅 SDR”固定在第二位；SDR表示普通动态范围而非清晰度等级，可包含4K、8K，不参与档位高低排序；实际档位实时按编排显示，清晰度初始8K在4K前。四类入口均不提供“自定义顺序”菜单项，常驻“编排”按钮控制编辑区，收起不清除顺序。编码选择和排序均表达偏好，选择某编码将其移至首位并保留其他编码，“自动”清空偏好。
- “画质与编码”标题右侧使用共享标题操作槽放置问号；点击说明最佳可用、手动选档、同档编码选择、SDR含义与编排保存操作，兼容键盘和触控。设置主体为滚动条预留稳定槽位，内容与滚动条之间桌面留16px、手机留12px，不让表单和分隔线贴住滚动条。
- 下拉选项沿用中性色选中底和粉色勾选，不使用粉色侧条、加粗或大面积粉色选中块。
- 全局质量默认显示“最佳可用”，点击编排才展示编辑器并初始化顺序；已有顺序在加载设置时不自动改脏草稿。最佳可用按保存的顺序选择首个可用档位；SDR按相同顺序先过滤HDR/杜比。选择具体档位保留编排顺序但不按其换档，新选择默认“不换档”，并直接说明缺少时不创建任务；主动允许换档时明确提示可能降至480P或更低。此指定档位规则与编排候选的优先级分开。
- 编排区列出固定完整候选：清晰度11档、音质6档、视频AVC/HEVC/AV1、音频AAC/FLAC/E-AC-3。名称固定，只能上下排序，没有添加、删除或逐行下拉。已有部分顺序仅在主动编辑时补齐，保存生效；原有每档编码限制保留。编码顺序独立于档位顺序，先选档位、同档再选编码；未列出的现有编码仍可使用，排在已列编码之后，不因未命中首选而禁止下载。桌面双列、手机单列滚动。
- 两类预设列表中的默认项同时使用粉色标题与“默认”标记，不依赖小标记单独表达当前状态。
- 编排区不显示“列表内档位都不可用时”“不下载”等策略；对应配置字段已移除。全部已编排档位未命中时使用其他现有可用轨道；用户手动指定具体画质/音质仍遵循单独的缺失质量策略，保持手动选4K的约定。并排编排区顶部对齐，不拉散较短列表。
- 下载时选择下载或命名预设会记住，目录与重名策略的临时调整仅作用于本次。设置页的默认命名仍通过页面保存；预设库的新增、编辑、删除即时保存，不顺带保存其他设置草稿。
- 主弹窗按内容自然取高，较短窗口滚动主体并保留操作区；手机底部大小提示单独成行。可选说明使用支持点击、键盘与触控的问号浮层，按钮复用 6px 圆角。
- 预设编辑器直接展示转换/封装标签与配置，不增加外层“更多选项”折叠。剪贴板自动识别失败静默处理，不用后台检测失败提示打断当前操作；主动粘贴失败仍在解析页反馈。

## 10. 尺寸依据与参考边界

| 来源 | 可核对的事实 | 能支持与不能支持的结论 |
| --- | --- | --- |
| [Google旧Material Web按钮源码](https://github.com/material-components/material-components-web/blob/master/packages/mdc-button/_button-shared-theme.scss) | 默认可见高度变量为36 CSS px | 说明36有特定组件出处，不是所有Android按钮或B站采用36的证据 |
| [AndroidX Material 3 small按钮token](https://github.com/androidx/androidx/blob/androidx-main/compose/material3/material3/src/commonMain/kotlin/androidx/compose/material3/tokens/ButtonSmallTokens.kt) | small容器高度为40dp | 组件体系和尺寸档位不同；不能借此直接把BDL按钮改成40dp |
| [微软Fluent UI React按钮源码](https://github.com/microsoft/fluentui/blob/master/packages/react-components/react-button/library/src/components/Button/useButtonStyles.styles.ts) | 中号图标按钮宽度约束32 CSS px，图标20px，上下padding各5px与1px边框；由此推得默认外框高32px | 这是桌面/Web组件的特定实现与推导，不是B站手机按钮实测 |
| [Android触控说明](https://support.google.com/accessibility/android/answer/7101858) | 推荐至少48×48dp触控热区，可见图形可以更小 | 约束可操作区域，不等于可见胶囊必须高48dp，更不能证明36dp最合适 |
| 用户提供的B站“我的”页截图 | 行内胶囊、顶部图标、图文入口、底部发布入口有不同视觉尺度 | 本次直接视觉参考；不能从单张图片读取布局文件、触控热区、sp字号或确切dp |

这些是公开组件/平台依据，没有据此声称已实测任何消费App的内部参数。Material官方规格页当前需要JavaScript，数值核对使用上述官方源码；版本不同的体系不能混成一张通用尺寸表。

用户截图文件为822×1920图像像素。人工查看，“发布”和“大会员中心”胶囊约58–60图像像素高，约占图宽7.1%–7.3%；这是目测近似，不是像素分割或设备实测。若仅假设逻辑视口宽390，则对应约27.5–28.5逻辑单位；此假设不能写成“B站按钮是28dp”。截图可能经过缩放，显示大小、字体缩放和设备密度也未知，需取得设备信息或在同设备等宽画面上比较。

参考图的价值是层级：头像和主标题可以突出，辅助胶囊保持轻巧，图文入口用组间距组织。不能把“紧凑”解释成所有元素统一缩小，也不能把账号入口、列表操作和主要下载动作套成同一按钮尺寸。
