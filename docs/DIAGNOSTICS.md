# 错误与诊断约定

## 错误信息

命令错误使用 `code`、简短的 `message` 和脱敏的 `detail`。提示可以简化，详情必须保留失败阶段和原始原因。新增错误边界不得仅取上层提示或覆盖先发生的错误。

- 文件操作：记录具体操作、路径、文件名/完整路径字节数、系统错误码及 I/O 类型。本地文件或下载状态解析失败立即返回，不作为 CDN 连接错误轮换地址重试。
- 接口请求：记录调用位置、域名/接口路径、真实连接/超时/响应读取标志和最多八层底层原因。响应模型解码保留预期类型与行列信息，移除响应中的字符串值，不记录原始响应正文。
- 解析取消：独立错误码 `parse_cancelled`；记录操作标识、来源、动作、解析对象、当前阶段、耗时及最初取消原因。区分主动停止、工作区清理、来源关闭、离开内容库（`library_deactivated`）、返回收藏夹列表（`library_folder_closed`）及账号变化（`account_changed`），不根据“解析已停止”推断网络或登录故障。创建任务的前端诊断在提交前保存入口（`library` / `parse`）、来源类型及所选分集数，切页或清理后仍保留原值。
- 下载：区分发送请求、读取响应体、本地文件操作、媒体处理和导出。网络失败记录地址序号、域名、最后原因和失败时配置；不把备用地址的错误覆盖为单一通用提示。
- Android 插件：保留异常类型、原因链和有限的调用栈，由 Rust 补充操作和输入/输出上下文。
- 数据库：保留 SQLite 错误类别和扩展码；打开与初始化失败附带数据库路径。
- 批量操作：每项失败保留任务标识、错误码和详情，即使批量命令本身成功返回，也必须记录失败项。

分类优先使用错误产生点提供的稳定错误码，再识别旧日志。禁止把文件名中的 HTTP 数字或 `is_timeout=false` 解释为对应网络故障。任务重试后，仅使用当前尝试的错误；相同时间戳沿用存储/事件的新到旧顺序。

## 保存、复制与导出

任务日志保存在任务数据库。尚未创建任务的命令失败、批量失败项及队列后台异常，写入同一数据库的 `operation_errors`。前端最近错误只是显示缓存；重启后由后端加载，全局诊断导出直接读取后端记录。

日志写入失败时，在原错误详情中附加写入失败原因，不替换原错误，也不递归尝试记录自身。后台错误保存后发出事件通知界面。

已接受的下载提交另存准备记录，包含提交入口、来源、处理数量、状态和错误；复制诊断和全局导出均可查看，离开原页面仍可处理。后台准备失败写入操作错误日志。正常的浏览停止不作为失败重复写入日志；账号变化和异常中断在准备记录中给出明确原因。任务已入队后即使准备结果保存失败，也保留真实的完成数量并报告保存错误，不将其改成可重复执行的规划失败。

应用内复制统一使用平台剪贴板：Android 使用原生 `ClipboardManager`，桌面使用原生剪贴板插件。浏览器预览使用 Web Clipboard API。不能把 Android WebView 中浏览器剪贴板 API 的存在当作其可用证据。

任务详情的复制内容使用最近 20 条日志和环境；单任务 JSON 导出最多包含 1000 条日志。全局导出包含每任务最近 50 条日志、最多 200 条操作错误及其发生时环境。设备信息采集失败会记录不可用状态和具体原因。

单条命令提示最多 4000 字符，详情最多 65536 个 Unicode 字符；超过时明确标记截断。前后端按 Unicode 字符计数，避免 emoji 导致末尾原因提前丢失。原因链超过八层也明确标记。

Android 导出先生成应用内报告，再打开系统保存窗口，让用户选择可访问的位置；取消保存不作为错误。保存失败时保留应用内原报告，并保留原生失败原因。桌面导出返回应用内文件路径。

保存和复制/导出前均进行脱敏：Cookie、鉴权头、签名查询参数、URL 用户名/密码等不得进入反馈材料。禁止将命令的整份参数或完整接口响应写入错误记录。

## 保留与清理

- 任务日志保留 30 天，每任务最多 1000 条。
- 操作错误保留 30 天，最多 200 条；启动和新增记录时清理过期/超量项。
- 已结束的准备记录保留 30 天，最多 100 条；可在全局准备任务中关闭单条记录。正在准备或等待重复项确认的记录不自动删除，最多 20 批。
- 应用内部诊断导出文件最多保留最近 10 份。
- “清理日志”删除操作错误和已完成、失败、已取消任务的日志；保留排队、暂停、运行中任务的日志、任务记录和媒体文件。
- “清理诊断文件”只处理应用内部按约定命名的诊断导出文件，不遍历用户目录。

日志清理释放数据库内部页面供后续复用，SQLite 文件大小不一定立即缩小。界面显示的日志用量是记录内容大小。

## 验证入口

复用 core 的 `diagnostics`、`storage`、`fetcher_resume` 及 tauri 的既有错误/持久化契约，前端复用 API、解析和传输诊断测试。涉及传播链的修改应验证真实文件/HTTP 错误、错误转换、重开数据库、JSON 导出、前端复制与脱敏，以及日志写入本身失败时仍保留主错误。

诊断链通过验证不代表某个用户环境故障已经定位。实际根因必须由对应版本的原生复现或反馈日志确认；进程被系统终止等未进入错误处理的事件不在操作错误记录覆盖范围内。
