# Architecture and ownership

BDL 按“领域真相在 Rust、会话交互在 Vue”的边界组织。跨边界数据必须使用稳定 DTO，不能把 Bilibili 原始响应或前端临时状态写入持久化模型。

## Rust workspace

### `bdl-core`

| 模块     | 所有权                                | 不变量                                                        |
| -------- | ------------------------------------- | ------------------------------------------------------------- |
| resolver | 输入识别、分页 API 与归一化来源树     | 列表解析不获取媒体流；只有按需 hydration 获取下载地址         |
| planner  | 选择、质量/编码策略与任务资源规划     | 一个选中分 P 对应一个稳定任务；资源 ID 可恢复且不依赖临时 URL |
| queue    | 任务、资源和状态模型                  | 状态转换显式；完成状态不能由前端推断                          |
| fetcher  | 重试、断点、分段、备用 URL 与限速     | `.bdlpart` 在原子完成前保留；取消必须中断阻塞请求             |
| muxer    | FFmpeg 探测和媒体封装                 | 容器能力在执行前验证；失败保留可诊断 stderr                   |
| nfo      | NFO 字段模板、XML 渲染与校验          | 只使用任务快照；文本转义；缺失来源信息不推断                |
| storage  | SQLite 任务、日志、账号摘要和完成记录 | 不存 Cookie；替换任务时保留日志；旧数据可向前读取             |

### `bdl-tauri`

| 模块              | 所有权                                   | 不变量                                              |
| ----------------- | ---------------------------------------- | --------------------------------------------------- |
| commands          | Tauri 参数校验、DTO 翻译和系统入口       | command 只做适配；领域规则下沉到专属模块            |
| parse_session     | 来源分页、合并、选择映射和按需 hydration | 分页累计不重复；占位选择在展开后仍指向正确分 P      |
| parse_owned       | 无状态浏览请求与持有输入的准备解析       | 请求 UUID 独立取消；不维护共享来源树缓存           |
| preparation       | 提交登记、后台准备、停止及重复项确认     | 回执与完成区分；页面清理不取消已接受的提交          |
| queue_coordinator | 重复任务、恢复与受保护状态转换           | 持久化成功后再发布状态；暂停/取消不会被 worker 覆盖 |
| queue_worker      | 并发调度、限速器、定时等待与结果收割     | 同时只有一个调度循环；展示进度合并不延迟任务命令    |
| media_finalize    | 附件选择、已完成资源定位和 NFO           | 只嵌入已完成且容器支持的文件；警告必须指出具体附件  |
| diagnostic_export | 诊断脱敏                                 | Cookie、鉴权头、代理凭据与签名查询参数不得导出      |
| secure_store      | 平台凭据持久化、加密与旧 Cookie 迁移     | Cookie 不进入 SQLite、日志或前端 DTO；macOS 仅落加密凭据文件 |
| state             | 持久状态组合与共享并发资源               | 不新增可独立测试的领域规则；新规则优先进入上述模块  |

## Shared desktop and mobile frontend

| 目录      | 所有权                             | 不变量                                                    |
| --------- | ---------------------------------- | --------------------------------------------------------- |
| `app/` | 两端页面的懒加载与工作区编排 | `App.vue` 选择系统对应外壳；工作区仅挂载对应页面 |
| `desktop/` | 桌面外壳、页面、专用组件和相邻样式 | 依赖共享层，不引用移动页面 |
| `mobile/` | 手机与平板的移动外壳、页面和触摸组件 | 依赖共享层；窗口宽度不改变系统能力 |
| `shared/features/` | 共用页面 composables 与业务表单 | 不复制状态、校验、请求或任务提交规则 |
| `shared/api/` | Tauri 命令 DTO 与调用 | 字段与 Rust 序列化形状一致，不包含视图推断 |
| `shared/stores/` | 跨页面会话状态与命令调用 | 后端任务状态是唯一真相；纯转换放入独立可测试模块 |
| `shared/ui/` | 可访问的共享控件和工作区模式 | 明暗主题、焦点、禁用、加载与错误状态使用统一 token |
| `shared/styles/` | 设计 token、基础布局和少量共享模式 | 页面样式不能重新定义品牌色或控件状态体系 |
| `shared/platform/` | 系统身份与平台适配入口 | 系统操作依赖平台身份，展示布局依赖可用窗口尺寸 |

前端仍使用一个 `apps/desktop` 工程，桌面与移动界面共用 API、stores 和 Rust 下载管线。依赖方向为 `app -> desktop/mobile -> shared`，ESLint 检查静态导入边界。源码职责与交互维护约定见 [前端说明](../apps/desktop/src/README.md)。

## 下载提交与浏览生命周期

普通下载使用 `selection_submit_tasks`。后端复制所选条目、选择和生效下载设置，保存准备记录并返回标识；网络补全、规划和入队由 Rust 异步运行时执行。前端仅在登记期间防止重复点击，登记后可切换页面。全局准备任务入口负责进度、原始错误、停止和重复项确认，真实下载状态仍由队列提供。

浏览首次解析、分页和按需补全传递来源快照与独立请求 UUID，不在后端保存整棵浏览来源树。前端使用工作区代次与来源实例标识丢弃迟到结果；相同收藏夹重新打开后，旧请求不得写回或取消新实例。准备任务只保留所需内容；未选条目保留空位置以维持命名中的原始序号。

准备任务排队串行执行，最多接受 20 批未结束提交。重复项待确认时只保留本次规划，不重复请求接口；用户确认后重新检查当前队列。停止与入队在同一准备记录锁下确定先后，停止准备不取消已入队下载。切换账号会停止尚未入队的准备任务。Android 执行活动合并下载和各准备操作的占用。

准备记录与运行输入分离：运行输入和待确认规划只存在本次进程中，记录保存在 SQLite。应用重启将未结束记录明确标为中断，用户可重新提交；不会自动重放入队操作。原有“后台解析下载”的逐条处理、成功检查点和失败项重试继续使用同一持有输入的规划核心，其分页循环和检查点仍属于前端会话，不提供重启续跑。

## Change routing

- 新来源或分页行为：从 `bdl-core/resolver` 开始，补归一化测试，再接 Tauri 与 UI。
- 下载状态或恢复：从 queue/coordinator 开始，先写状态转换测试。
- 新设置：Rust schema、验证和迁移优先，然后扩展前端 typed form。
- UI 视觉改动：先扩展 token/共享 primitive，再修改页面；同时验证浅色、深色和窄窗口。
- 诊断字段：默认视为敏感，先更新脱敏测试，再允许进入导出。
