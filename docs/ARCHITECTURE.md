# Architecture and ownership

BDL 按“领域真相在 Rust、会话交互在 Vue”的边界组织。跨边界数据必须使用稳定 DTO，不能把 Bilibili 原始响应或前端临时状态写入持久化模型。

## Rust workspace

### `bdl-core`

| 模块     | 所有权                                | 不变量                                                        |
| -------- | ------------------------------------- | ------------------------------------------------------------- |
| resolver | 输入识别、分页 API 与归一化来源树     | 列表解析不获取媒体流；只有按需 hydration 获取下载地址         |
| planner  | 选择、质量/编码策略与任务资源规划     | 一个选中分 P 对应一个稳定任务；资源 ID 可恢复且不依赖临时 URL |
| queue    | 任务、资源和状态模型                  | 状态转换显式；完成状态不能由前端推断                          |
| fetcher  | 重试、断点、分段、备用 URL 与限速     | `.bdlpart` 在原子完成前保留；取消必须中断阻塞请求             |
| muxer    | FFmpeg 探测和媒体封装                 | 容器能力在执行前验证；失败保留可诊断 stderr                   |
| storage  | SQLite 任务、日志、账号摘要和完成记录 | 不存 Cookie；替换任务时保留日志；旧数据可向前读取             |

### `bdl-tauri`

| 模块              | 所有权                                   | 不变量                                              |
| ----------------- | ---------------------------------------- | --------------------------------------------------- |
| commands          | Tauri 参数校验、DTO 翻译和系统入口       | command 只做适配；领域规则下沉到专属模块            |
| parse_session     | 来源分页、合并、选择映射和按需 hydration | 分页累计不重复；占位选择在展开后仍指向正确分 P      |
| queue_coordinator | 重复任务、恢复与受保护状态转换           | 持久化成功后再发布状态；暂停/取消不会被 worker 覆盖 |
| queue_worker      | 并发调度、限速器、定时等待与结果收割     | 同时只有一个调度循环；展示进度合并不延迟任务命令    |
| media_finalize    | 附件选择、已完成资源定位和 NFO           | 只嵌入已完成且容器支持的文件；警告必须指出具体附件  |
| diagnostic_export | 诊断脱敏                                 | Cookie、鉴权头、代理凭据与签名查询参数不得导出      |
| secure_store      | 平台凭据持久化、加密与旧 Cookie 迁移     | Cookie 不进入 SQLite、日志或前端 DTO；macOS 仅落加密凭据文件 |
| state             | 持久状态组合与共享并发资源               | 不新增可独立测试的领域规则；新规则优先进入上述模块  |

## Desktop frontend

| 目录      | 所有权                             | 不变量                                                    |
| --------- | ---------------------------------- | --------------------------------------------------------- |
| `api/`    | Tauri 命令 DTO 与调用              | 字段与 Rust 序列化形状一致，不包含视图推断                |
| `stores/` | 跨页面会话状态与命令调用           | 后端任务状态是唯一真相；纯转换放入独立可测试模块          |
| `pages/`  | 页面编排                           | 页面组合 store、领域 composable 与共享 UI，不复制状态规则 |
| `ui/`     | 可访问的共享控件和工作区模式       | 明暗主题、焦点、禁用、加载与错误状态使用统一 token        |
| `styles/` | 设计 token、基础布局和少量共享模式 | 页面样式不能重新定义品牌色或控件状态体系                  |

## Change routing

- 新来源或分页行为：从 `bdl-core/resolver` 开始，补归一化测试，再接 Tauri 与 UI。
- 下载状态或恢复：从 queue/coordinator 开始，先写状态转换测试。
- 新设置：Rust schema、验证和迁移优先，然后扩展前端 typed form。
- UI 视觉改动：先扩展 token/共享 primitive，再修改页面；同时验证浅色、深色和窄窗口。
- 诊断字段：默认视为敏感，先更新脱敏测试，再允许进入导出。
