# Android 适配计划

状态：仅规划，当前优先完成 Linux x86_64。本文不表示 Android 已可构建或发布。

## 目标与复用范围

复用 Rust 解析、画质偏好、任务规划、限速和配置默认值机制，以及 Vue 的业务状态和表单。首次面向 ARM64 手机；其他架构、最低 Android 版本和分发渠道在原型验证后确定。

Linux 阶段沿用桌面的 FFmpeg 进程、普通文件路径和现有凭据接口，不为了尚未实现的移动端增加空适配器或一个包办所有操作的平台接口。

## 实施顺序

1. **入口与系统能力。** 将 Tauri 启动组装整理为可复用入口，增加移动入口；隔离桌面窗口、更新、目录选择与打开文件操作。按平台提供能力，界面只展示实际支持的操作。凭据接口沿用 `SecureStore` 的后端边界，Android 使用 Keystore 保护加密密钥，不沿用当前非 macOS Unix 的 Linux keyring 条件。
2. **媒体处理原型。** 将“输入轨道、输出封装、字幕和封面”作为媒体处理接口；桌面实现调用 FFmpeg，Android 实现调用随包分发的 FFmpeg 原生库。接口不暴露命令行参数或 FFmpeg 可执行文件路径。先验证真实文件合并，再接队列；包含取消、错误和完成结果。
3. **输出与恢复。** 下载分片、SQLite、临时媒体文件放在应用私有目录；最终成品通过输出目标接口保存到用户授权的位置。普通路径与 SAF/content URI 明确区分，不将 URI 强行转换为 PathBuf。保存授权、重名策略、空间不足、授权失效、保存中断和重试行为；最终保存成功后才将任务标记完成。
4. **后台执行。** 把当前由前端持续驱动的“解析全部并下载”调度迁到后端。接入适用的 Android 后台执行机制与通知，按目标 SDK 核查前台服务类型、启动条件及运行限制。不能承诺锁屏后无限运行；支持进程终止后的任务恢复，页面销毁不应丢失调度状态。
5. **手机界面与发布。** 调整窄屏导航、下载弹窗、目录授权和通知权限流程。确定最低系统版本，验证原生库页面大小要求与 ABI 打包，完成签名、升级及权限撤销测试。

## FFmpeg 裁剪范围

采用固定版本、可重复构建的 NDK 编译脚本，不依赖已停止维护的原 FFmpegKit 二进制。先关闭可选组件，再按实际输入和输出逐项启用；最终白名单以测试素材和构建依赖为准。

- 保留 MP4/M4A、Matroska 等产品实际使用的封装，以及源站实际返回格式的必要解封装能力。
- 保留 AVC、HEVC、AV1 及实际音频轨道所需的解析、码流处理和元数据复制。流复制无需视频编码器，但不能据此删除所有解析器和 bitstream filter。
- 保留 HDR 色彩信息及杜比视界配置的读写；用样本比较合并前后元数据，不能只检查退出码。
- 保留现有字幕、封面功能所需组件；MP4 字幕转换为 `mov_text`，不能禁用全部编码器。独立弹幕和 NFO 输出沿用现有逻辑。
- 去掉无用的音视频编码器、滤镜、采集设备、网络协议、播放器与命令行工具。下载网络请求由现有 Rust 下载器负责。
- 按 ABI 分发，优化并剥离发布库的调试符号，另存符号用于排错。记录原生库大小、安装包压缩大小及安装占用，不预先承诺体积。
- 随构建固定许可证配置、源码及修改记录，落实所用 FFmpeg 组件的分发要求。

## 验收门槛

- 与桌面用相同素材验证 MP4/MKV、纯音频、字幕、封面、HDR 和杜比视界；无法封装的组合明确报错，不自动转码或静默降级。
- 无需用户另装 FFmpeg 或指定其路径；设备不能播放某种编码，不应等同于不能下载或合并该轨道。
- 验证锁屏、切后台、杀进程重启、断网恢复、授权撤销、空间不足及最终文件保存失败；不损坏现有文件，也不误报完成。
- 使用旧版配置缺字段时的通用默认值机制；保留用户有效设置，不引入按版本号串联的配置迁移。
