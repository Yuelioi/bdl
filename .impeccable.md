## Design Context

### Users
BDL is a desktop downloader for Bilibili power users who parse links, select many videos, monitor transfers, and recover failed tasks.

### Brand Personality
Quiet, utilitarian, reliable. The UI should feel like an efficient tool, not a marketing page or decorative dashboard.

### Aesthetic Direction
Compact, task-focused product UI with clear hierarchy, achromatic cool-neutral surfaces, a restrained Bilibili-pink signal color, stable layouts, and equivalent light/dark themes. Structural layers must never be pink-tinted: light mode uses clean whites and cool grays, while dark mode uses a charcoal surface ladder. Pink is reserved for primary actions, selection, focus, and small status signals rather than large surfaces. Common actions and current task state should be visible immediately; secondary technical details should be available behind tabs or disclosure. The desktop window uses a slim custom title bar rather than native decorations.

### Design Principles
- Prioritize download state, progress, retry, and open-file/open-folder actions.
- Keep parse, normalized selection, transfer, and settings as separate workflows.
- Treat parsed metadata as a content selector, not a parsing-progress dashboard: show total items, current selection, and filtered matches without exposing hydration or visibility internals.
- Avoid empty placeholder pages and decorative cards.
- Make long titles, paths, resource errors, and logs readable without horizontal scrolling.
- Use Nuxt UI and Tabler icons through the local wrapper components so controls share one BDL theme.
- Use one workspace skeleton across pages: a quiet top navigation or workflow row, one primary content surface, and contextual selection actions anchored at the bottom.
- Let task state determine information density: completed work shows outcomes and file actions, while transfer metrics appear only for active work.
- Keep selection behavior consistent across parse and transfer flows: selected count on the left, only applicable actions on the right, and no disabled-action clutter.
- Keep docs and UI decisions self-contained in BDL product requirements; do not cite other downloader projects as references.
